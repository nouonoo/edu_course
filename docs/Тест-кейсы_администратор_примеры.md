## TC-ADM-SCORM-N001 — негативный

<table>
  <tr>
    <th>Id теста</th>
    <th>Название теста</th>
    <th>Краткое описание теста</th>
  </tr>
  <tr>
    <td>TC-ADM-SCORM-N001</td>
    <td>Загрузка SCORM 1.2 при поддержке runtime только SCORM 2004</td>
    <td>
      Проверка граничного сценария: администратор импортирует пакет SCORM 1.2
      (<code>&lt;schemaversion&gt;1.2&lt;/schemaversion&gt;</code>). LMS должна либо отклонить
      такой пакет с понятным сообщением, либо не создавать ложное впечатление полной
      совместимости. Платформа по ТЗ поддерживает SCORM 2004; API SCORM 1.2
      (<code>window.API</code>, <code>LMSInitialize</code>) в проекте не реализован —
      используется только <code>scorm-api-2004.js</code>. Приоритет: P1. Тип: N, I.
      <br><br>
      <strong>Предусловия:</strong> администратор авторизован; подготовлены два тестовых ZIP:
      (А) SCORM 2004 — контрольный эталон; (Б) SCORM 1.2 — устаревший пакет с тем же
      учебным содержимым, но другой версией манифеста.
    </td>
  </tr>
  <tr>
    <th>Этапы теста:</th>
    <th>Ожидаемый результат:</th>
    <th>Фактический результат:</th>
    <th>Статус (успешно/завершилось ошибкой)</th>
  </tr>
  <tr>
    <td>
      1. Войти как администратор<br>
      2. Загрузить контрольный пакет SCORM 2004 («Эталон 2004»)<br>
      3. Зафиксировать значение <code>version</code> в <code>scorm_meta.json</code><br>
      4. Загрузить пакет SCORM 1.2 («Тест SCORM 1.2»)<br>
      5. Сравнить <code>scorm_meta.json</code> обоих курсов: поле <code>version</code><br>
      6. Открыть <code>player.html</code> курса SCORM 1.2 и проверить, какой API подключён<br>
      7. Назначить курс SCORM 1.2 обучающемуся (через эксперта), открыть его и пройти
         первый SCO<br>
      8. Проверить таблицы <code>Section_progress</code>, <code>User_result</code> и файл
         <code>uploads/scorm_state/*.json</code><br>
      9. Проверить, отображается ли в интерфейсе администратора предупреждение
         о неподдерживаемой версии SCORM
    </td>
    <td>
      1. Для SCORM 2004: <code>version = "2004"</code>, прогресс сохраняется<br>
      2. Для SCORM 1.2 — один из безопасных вариантов:<br>
         &nbsp;&nbsp;а) импорт отклонён с сообщением «Поддерживается только SCORM 2004»; или<br>
         &nbsp;&nbsp;б) импорт разрешён, но в каталоге явно указано «SCORM 1.2 — не поддерживается»,
         запуск без записи прогресса невозможен<br>
      3. После прохождения SCO в SCORM 1.2 не должны появляться некорректные записи
         о 100% завершении «по умолчанию»<br>
      4. Администратор не должен ошибочно считать SCORM 1.2 полностью рабочим
         наравне с SCORM 2004
    </td>
    <td>
      1. Контрольный пакет SCORM 2004 импортирован успешно:
         <code>"version": "2004"</code><br>
      2. Пакет SCORM 1.2 также принят сервером (<code>POST /api/admin/courses → 200</code>),
         курс отображается в каталоге<br>
      3. В <code>scorm_meta.json</code> курса SCORM 1.2 записано <code>"version": "1.2"</code> —
         детектор версии в <code>scorm_importer.py</code> отработал корректно<br>
      4. Однако <code>player.html</code> обоих курсов подключает один и тот же
         <code>scorm-api-2004.js</code>; объекта <code>window.API</code> (SCORM 1.2) нет<br>
      5. Контент SCORM 1.2 при запуске вызвал <code>API.LMSInitialize()</code> —
         в консоли ошибка «API is undefined», CMI-данные не отправлены на
         <code>POST /api/scorm/&lt;course_id&gt;/state</code><br>
      6. В <code>Section_progress</code> и <code>User_result</code> записи не появились,
         файл состояния SCORM не создан<br>
      7. В интерфейсе <code>admin-courses.html</code> предупреждение о версии 1.2
         не отображается — администратор видит курс как обычный SCORM<br>
      8. <strong>Вывод проверки:</strong> различие версий фиксируется на этапе импорта,
         но runtime LMS поддерживает только SCORM 2004; импорт SCORM 1.2 создаёт
         «тихую» неработоспособность
    </td>
    <td>
      Завершилось ошибкой<br>
      <small>(тест выявил дефект UX/валидации: SCORM 1.2 принимается в каталог,
      но не может корректно работать; рекомендуется блокировка импорта или
      явное предупреждение администратору)</small>
    </td>
  </tr>
</table>
