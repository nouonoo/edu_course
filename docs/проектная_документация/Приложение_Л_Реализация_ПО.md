## Л.1. Авторизация пользователя

При входе в АИС пользователю предоставляется форма авторизации на странице `login.html`. После ввода email и пароля frontend-модуль `auth.js` отправляет запрос `POST /api/login`; сервер проверяет учётные данные в таблице `Users`, формирует JWT-токен и возвращает роль пользователя. В зависимости от роли выполняется переход: администратор — на `users.html`, эксперт — на `assignments.html`, обучающийся — на `instruction.html`. При неверном пароле или пустых полях пользователь остаётся на форме входа, отображается сообщение об ошибке.

**Рисунок Л-1 – Форма авторизации**

На рисунке Л-1 представлена форма входа с полями «Логин» и «Пароль» и кнопкой подтверждения.

**Рисунок Л-2 – Код реализации авторизации (фрагмент `auth.js` и `app.py`)**

Обработка формы на клиенте и выдача токена на сервере реализованы следующим образом:

```javascript
// frontend/auth.js
const response = await fetch(`${API_URL}/login`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ login, password })
});
const data = await response.json();
saveAuthSession(data.token, data.role, data.home_page);
window.location.href = data.home_page;
```

```python
# backend/app.py
@app.route('/api/login', methods=['POST'])
def login():
    data = request.get_json()
    user = db.authenticate_user(data.get('login'), data.get('password'))
    if not user:
        return jsonify({"message": "Неверный логин или пароль"}), 401
    role = db.get_user_role(user.user_id)
    token = create_access_token(identity={"user_id": user.user_id, "role": role})
    return jsonify({"token": token, "role": role, "home_page": db.get_home_page(role)})
```

JWT выбран вместо серверных сессий, поскольку токен передаётся в URL при запуске курса (`authToken`) и не требует cookie между портами 8000 и 5000.

## Л.2. Разграничение доступа к страницам

После авторизации при открытии любой страницы LMS вызывается `bootstrapAuth()` из `common.js`. Функция проверяет наличие токена, запрашивает `GET /api/auth/me` и сверяет роль пользователя со списком `PAGE_ACCESS`. Если роль не допускается на текущую страницу, браузер перенаправляется на стартовую страницу роли. Так реализован запрет прямого перехода обучающегося на `users.html` или эксперта на `admin-courses.html`.

**Рисунок Л-3 – Переход на недоступную страницу (редирект на home_page)**

**Рисунок Л-4 – Код реализации контроля доступа (фрагмент `common.js`)**

```javascript
const PAGE_ACCESS = {
    'users.html': ['admin'],
    'admin-courses.html': ['admin'],
    'assignments.html': ['expert'],
    'instruction.html': ['student', 'expert'],
    'rating.html': ['student', 'expert', 'admin'],
    'profile.html': ['student', 'expert', 'admin']
};

async function bootstrapAuth() {
    const page = getCurrentPage();
    const allowed = PAGE_ACCESS[page];
    if (!allowed) return true;
    const session = await ensureAuthSession();
    if (!session || !allowed.includes(session.role)) {
        window.location.href = session?.home_page || 'login.html';
        return false;
    }
    return true;
}
```

Централизованная таблица `PAGE_ACCESS` упрощает сопровождение: при добавлении страницы достаточно указать допустимые роли в одном месте.

## Л.4. Назначение курса экспертом

На странице `assignments.html` эксперт просматривает каталог курсов и для каждого может открыть модальное окно **«Назначить курс»**. Кнопка **«Статистика прохождения»** переводит на `rating.html` с предзаполненным фильтром по курсу.

**Рисунок Л-8 – Модальное окно назначения курса**

**Рисунок Л-9 – Код реализации назначения курса (фрагмент `database.py`)**

```python
def create_assignment(self, user_id, course_id, assigned_by, date_from, date_to):
    active = self.get_active_assignment(user_id, course_id)
    if active:
        return None, 'У пользователя уже есть активное назначение по этому курсу'
    sql = """
        INSERT INTO Assignments (user_id, course_id, assigned_by, date_from, date_to, status)
        OUTPUT INSERTED.assignment_id
        VALUES (?, ?, ?, ?, ?, 'active')
    """
    assignment_id = self._execute_scalar(
        sql, (user_id, course_id, assigned_by, date_from, date_to)
    )
    return assignment_id, None
```

Ограничение одного активного назначения предотвращает дублирование прогресса и конфликт записей в `Section_progress`.

## Л.5. Прохождение нативного курса и сохранение прогресса

Курс «Безопасность» открывается как одностраничное приложение (`index.html`). Модуль `lms-bridge.js` при инициализации загружает манифест и сохранённый прогресс. При переходе между разделами вызывается `completeSection`: на сервер уходит `POST /api/courses/<id>/sections/<section_id>/complete`. Backend обновляет `Section_progress`, пересчитывает сумму баллов и записывает промежуточный итог в `User_result`. Кнопка «Далее» заблокирована, пока не решены все интерактивы экрана (`CourseInteractions.isGateReady()`). На экране «Заключение» вызывается `finishCourse` — назначение переводится в статус `passed` или `failed` в зависимости от порога 70 %.

**Рисунок Л-10 – Экран раздела нативного курса с интерактивным заданием**

**Рисунок Л-11 – Код сохранения прогресса раздела (фрагмент `database.py`)**

```python
def complete_section(self, user_id, course_id, assignment_id, section_id,
                     is_practical, passed_first_try, section_weight):
    assignment = self.get_assignment_by_id(assignment_id)
    if not assignment or assignment.user_id != user_id:
        return None, 'Назначение не найдено'
    if assignment.status != 'active':
        return None, 'Назначение уже завершено'
    score, first_failed = calculate_section_score(
        section_weight, is_practical, passed_first_try
    )
    # INSERT или UPDATE Section_progress ...
    total = self._recalculate_assignment_score(assignment_id)
    return {"total_score": total, "section_score": score}, None
```

Расчёт баллов вынесен в `course_progress.py`, чтобы логику оценки можно было проверять модульными тестами без подключения к БД.

def create_user(self, data):

                           password_hash, photo, phone, birthday, status)

        VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)

## Л.7. Функция поиска

На страницах **«Пользователи»** и **«Курсы»** реализована функция поиска. Пользователь вводит запрос в поисковую строку; frontend передаёт параметр `search` в API (`GET /api/admin/users?search=` или `GET /api/courses?search=`), backend выполняет фильтрацию по ФИО, email или названию курса. На странице курсов список обновляется без перезагрузки страницы при каждом вводе символа.

**Рисунок Л-15 – Функция поиска по названию (роль «Администратор», страница «Курсы»)**

На рисунке Л-15 показан ввод запроса в поле поиска и отфильтрованный список курсов (например, «Страдающая методология» при запросе «страдаю»).

**Рисунок Л-16 – Код реализации поиска (фрагмент `database.py`)**

```python
def get_all_users(self, search=None):
    sql = """
        SELECT U.user_id, U.surname, U.name, U.patronymic, U.email, ...
        FROM Users U
        WHERE 1=1
    """
    params = []
    if search:
        sql += " AND (U.surname LIKE ? OR U.name LIKE ? OR U.email LIKE ?)"
        pattern = f"%{search}%"
        params.extend([pattern, pattern, pattern])
    ...

def get_all_courses(self, search=None):
    sql = "SELECT course_id, title, description, storage, date FROM Courses WHERE 1=1"
    params = []
    if search:
        sql += " AND title LIKE ?"
        params.append(f"%{search}%")
```

Поиск выполняется на стороне сервера через `LIKE`, чтобы не загружать в браузер полный список при большом числе записей.
